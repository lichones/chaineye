# ChainEye 실무자 검증 및 3분 데모

## 수상권 진입을 위한 최소 실무 검증

대상은 AML·컴플라이언스·블록체인 포렌식 실무자 3명이다. 실제 고객정보나 실제 의심거래는 받지 않고 공개 Elliptic 사례만 사용한다. 검토자 이름·조직 공개 범위는 검토자가 결정한다.

### 검토 사례

| 사례 | 입력 | 화면의 의도 |
|---|---:|---|
| A | `70424581` | 임계값 이상 모델 양성. 불법 확정이 아닌 우선 검토 |
| B | `114498409` | 임계값 미만 모델 음성. 정상 확정이 아닌 낮은 우선순위 |
| C | `999999999999` | 데이터 범위 밖. 점수·보고서·STR 권고 생성 억제 |

### 검토자 과제

각 사례의 정답 라벨은 먼저 보여주지 않는다.

1. 화면만 보고 `우선 검토 / 보류 / 낮은 우선순위` 중 하나를 선택한다.
2. 첫 판단까지 걸린 시간을 초 단위로 기록한다.
3. 판단에 사용한 화면 요소와 신뢰하지 않은 요소를 말한다.
4. 보고서에서 단정·환각·자동 STR 결정으로 읽히는 문장을 표시한다.
5. 다음 조사에 필요한 독립 원천자료를 말한다.

### 제출 자료에 넣을 수 있는 문장

실제 검토가 끝난 뒤에만 숫자를 채운다.

- `[N]명의 AML·포렌식 실무자가 공개 사례 3건을 검토했다.`
- `미평가 처리에 대해 [N/N]명이 0점 정상 판정보다 안전하다고 평가했다.`
- `검토자는 [요소]를 채택했지만 [요소]는 [이유] 때문에 조사 증거로 거부했다.`
- `피드백 후 [변경사항]을 적용했고 첫 판단 시간 또는 이해도가 [전/후]로 변했다.`

검토를 하지 못했다면 위 문장을 제출 자료에 넣지 않는다.

## 3분 심사 데모 시나리오

### 0:00~0:25 - 문제 정의

“AML 모델의 가장 위험한 오류는 틀린 점수만이 아닙니다. 모르는 입력에서도 그럴듯한 점수와 보고서를 만드는 것입니다. ChainEye는 모델이 어디까지 아는지 먼저 확인합니다.”

### 0:25~1:20 - 검토 후보 사례

1. `70424581`을 클릭한다.
2. 29점과 검토 임계값 23점을 짚는다.
3. “우선 검토 / 모델 양성·불법 확정 아님”을 읽는다.
4. SHAP은 모델 설명, 그래프는 방향성 인접 관계임을 설명한다.
5. 보고서의 실제 생성 경로 배지를 보여준다.

### 1:20~2:05 - 미평가 사례

1. `999999999999`를 클릭한다.
2. 점수가 사라지고 “평가 불가”가 나오는 것을 보여준다.
3. “판단 거부·생성 억제” 배지를 짚는다.
4. “점수뿐 아니라 보고서와 STR 권고까지 함께 멈추는 것이 차별점”이라고 말한다.

### 2:05~2:35 - 재현 증거

Jupyter Notebook에서 다음 출력만 빠르게 보여준다.

- 독립 시간 테스트 F1 0.711 / PR-AUC 0.674 재계산 PASS
- 혼동행렬 `[[15249, 338], [300, 783]]`
- 선택 임계값에서 테스트 1,000건당 검토 후보 약 67건
- 공개 배포본 parity gate PASS
