3. 문제 정의 및 제안 배경 *

문제: 모델 경보가 곧 사건 판단처럼 보인다

가상자산사업자와 금융회사의 AML 분석관은 한정된 시간 안에 많은 경보를 검토한다. 그러나 기존 화면은 점수만 강조하는 경우가 많아, 모델이 학습하지 않은 입력까지 0점 또는 정상으로 오인하거나 모델 양성을 범죄 확정으로 확대 해석할 위험이 있다.

적용 범위 불명확실시간 주소와 벤치마크 거래 ID를 구분하지 않으면 모델이 모르는 입력에도 그럴듯한 결과가 만들어진다.
설명과 증거의 혼동SHAP은 모델 설명이지만 실제 거래 증거처럼 읽힐 수 있고, 그래프 인접성은 소유권·범죄 관계를 입증하지 않는다.
자동 문서의 과신근거가 없는 상태에서 자연스러운 보고서가 생성되면 분석관에게 잘못된 확신을 줄 수 있다.

생성형 AI의 역할과 현재 공개 경로

Claude·OpenAI 생성 경로는 점수, 임계값, 모델 라벨, SHAP 기여도, 그래프 통계만 입력받아 검토 지원 문장을 작성하도록 구현했다. 생성형 AI는 점수·경로를 만들거나 변경하지 않으며, 입력에 없는 거래소·인물·주소를 생성하지 않도록 프롬프트를 제한한다.

다만 API 키가 없는 공개 MVP에서는 결정론적 템플릿이 동작한다. 화면의 배지가 실제 생성 경로를 Claude / OpenAI / 결정론적 템플릿 / 생성 억제로 공개하므로 생성형 AI 사용 여부를 숨기지 않는다. 미평가 입력은 LLM 호출 자체를 하지 않으며 API에서도 보고서 요청을 거부한다.

제출 원칙: 공개 URL에서 생성형 AI provider를 켜지 않는다면 “생성형 AI가 실제 보고서를 생성한다”고 주장하지 않는다. 본선 전 서버 Secret으로 활성화할 경우에도 동일한 근거 제한·출처 배지·템플릿 폴백을 유지한다.

6. 기대 효과 및 확장 가능성 *

현재 MVP에서 입증한 효과

  • 데이터 범위 밖 샘플에서는 모델 점수와 자동 보고서가 생성되지 않는 것을 API·브라우저 계약 테스트로 확인했다.
  • 모델 장애 시 실데이터처럼 보이는 목업을 반환하지 않고 503으로 실패해 운영자가 오류를 인지하게 했다.
  • 반올림된 화면 점수가 아니라 원시 확률로 임계값을 판정해 API·그래프 경계 불일치를 제거했다.
  • 보고서에서 모델 출력, 모델 기여도, 그래프 관찰 사실, 분석관 결정을 분리했다.
