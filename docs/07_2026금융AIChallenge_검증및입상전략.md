# 2026 금융 AI Challenge 검증 및 입상 전략

작성일: 2026-08-19

## 1. 결론

체인아이는 현재 **작동하는 기술 MVP**이지만, “Chainalysis/TRM의 축소판”으로 제출하면 수상권 차별성이 약하다. 제출 포지션은 다음 한 문장으로 고정한다.

> 체인아이는 가상자산 범죄를 확정하는 도구가 아니라, AML 모델이 언제 점수를 내고 언제 판단을 거부해야 하는지를 공개·검증하는 모델 보증 계층이다.

핵심 데모는 고위험 사례가 아니라 데이터 범위 밖 거래 `999999999999`이다. 0점 정상으로 처리하지 않고 평가 불가로 중단하며 자동 보고서와 STR 권고도 생성하지 않는 장면이 가장 방어 가능한 차별점이다.

## 2. 독립 검증 결과

세 개의 읽기 전용 검토 트랙으로 저장소와 CTI-Vault를 교차 점검했다.

| 검토 트랙 | 판정 | 핵심 결과 |
|---|---|---|
| 아키텍처·Bitcoin 의미론 | 조건부 GO | 실거래 주소는 온체인 관측으로만 분리 가능. 기존 ML 점수 적용은 금지 |
| 대회·제품 포지셔닝 | 피벗 권고 | 추적 제품 경쟁은 불리하며 판단 거부·출력 계약이 유일하게 방어 가능한 차별점 |
| AML·모델 리스크 | 조건부 GO | 시간 분할은 재현되지만 라이브 지갑 점수, CTI·휴리스틱·ML 통합 점수는 금지 |

공통 합의는 다음과 같다.

- Elliptic 익명 정수 txId 모델은 실제 Bitcoin 주소나 64자리 실거래 txid에 적용할 수 없다.
- `illicit` 라벨은 확인된 자금세탁 경로가 아니며 SHAP `feat_i`는 조사 증거가 아니라 모델 내부 기여도다.
- CTI 주장, 온체인 관측 사실, 휴리스틱 노출, ML 예측을 한 점수로 합치면 안 된다.
- 실거래 주소 조회를 붙이더라도 별도 `/onchain/*` 네임스페이스와 별도 화면에서 “모델 미적용”으로 제공해야 한다.

## 3. CTI-Vault 연동 판정

금보원 공개 웹서비스의 핵심 기능으로는 **NO-GO**다.

- 로컬 CTI-Vault의 wallet 항목은 Bitcoin·Tron·EVM과 잘못 분류된 해시가 섞여 있어 필드명만으로 체인을 신뢰할 수 없다.
- Bitcoin 항목도 확인·귀속이 끝난 공개 IOC가 아니라 제한 배포 대상의 검토 자료다. 구체적인 주소·사건·건수는 공개 저장소 문서에 옮기지 않는다.
- 공개 Esplora에 주소를 질의하면 어떤 주소를 조사하는지 제3자에게 노출된다. 제한 배포 주소를 공개 서비스에서 실시간 조회하면 안 된다.
- Elliptic 모델과 실제 주소 사이에는 조인 키가 없어 기존 위험점수와 연결되지 않는다.

따라서 제출물에는 CTI-Vault 원본 주소·사건명을 넣지 않는다. CTI 연동을 시연하려면 공개 배포가 허용된 합성 또는 공개 IOC만 사용하고, 결과는 “출처가 있는 주장” 표로만 보여준다.

## 4. 이번 검증에서 수정한 실제 결함

1. `/score`는 원시 확률을 사용하고 `/trace`는 반올림 정수를 사용하던 판정 불일치를 원시 확률 기준으로 통일했다.
2. 그래프 API의 `illicit`와 `paths`를 `modelPositive`와 `candidatePaths`로 바꿔 확정 범죄 의미를 제거했다.
3. 모델 로드 실패 시 합성 데이터를 LIVE 응답처럼 내보내던 기본 폴백을 제거했다. 기본은 503이며 명시적 개발 설정에서만 MOCK을 허용한다.
4. `/health`가 서버 확인 모드(`model|mock|unavailable`)를 반환하고 프론트가 그 값을 표시하도록 했다.
5. GCN 산출물에 남아 있던 무효 LightGBM 0.776/0.936 비교를 제거하고 `not_comparable`로 명시했다.
6. 기획서·기능명세서의 주소 실시간 스코어링, LLM 미구현, 배포 미완료 등 코드와 다른 설명을 현재 구현에 맞췄다.
7. 보고서 응답에 실제 생성 경로(`claude|openai|template`)를 추가해 생성형 AI 사용 여부를 화면에서 숨기지 않도록 했다.

## 5. 생성형 AI 전략

공식 기획서 양식은 생성형 AI의 역할을 필수로 묻는다. 현재 Claude·OpenAI 기반의 근거 제한 보고서 생성 경로와 키 없는 템플릿 폴백은 구현되어 있다.

제출 시 지켜야 할 선은 다음과 같다.

- 생성형 AI는 점수, 임계값, 라벨, 경로를 만들거나 변경하지 않는다.
- 입력으로 전달된 모델 수치와 그래프 통계를 서술형으로 정리하는 역할만 맡는다.
- 응답의 `generator`와 화면 배지로 실제 생성 경로를 공개한다.
- 평가 불가 입력에서는 생성형 AI를 호출하지 않는다.
- 생성 결과는 담당자 검토 전 STR 또는 수사 판단으로 사용하지 않는다.

API 키 없는 브라우저 로컬 모델은 Transformers.js로 구현 가능하지만, 한국어가 가능한 0.5B급 모델은 최초 다운로드가 수백 MB이고 WebGPU·메모리 편차가 커서 현재 심사 URL의 주 경로로 넣지 않는다. 품질과 대상 브라우저를 검증하지 못한 상태에서 추가하면 예제 안정성이 더 나빠진다. 공개 심사 URL에서 생성형 AI를 실제 시연하려면 서버 Secret으로 한 provider를 켜고, 실패 시 템플릿으로 폴백하는 현재 구조가 더 안전하다. 키를 사용하지 않기로 결정하면 기획서에는 생성형 AI를 사용했다고 쓰지 말고, 템플릿 기반 설명 생성으로 정직하게 낮춰야 한다.

## 6. 입상 가능성 판단

현재 상태는 기술 완성도는 높지만 실효성 증거가 부족한 중상위권이다. 수상권 진입 조건은 새 기능 추가보다 아래 네 가지다.

### P0 — 제출 전 반드시

1. AML/컴플라이언스 실무자 최소 1명의 블라인드 검토를 `docs/05_AML_실무자_검토표.md`로 실제 수행한다.
2. `70424581`, `114498409`, `999999999999` 세 사례의 입력·예상 결과·제한사항을 기능명세서 첫 페이지에 고정한다.
3. 제출 URL을 2026-09-07 11:00부터 09-11 23:59까지 계속 접근 가능하게 하고 콜드스타트 예열·녹화 백업을 준비한다.
4. 생성형 AI를 심사 URL에서 실제 켤지 결정한다. 켠다면 근거 제한·출처 배지·폴백을 시연하고, 끈다면 관련 과장 표현을 모두 제거한다.

### P1 — 수상권 강화

1. 임계값별 precision/recall/분석관 검토량 곡선과 고정 처리용량 기준 `precision@K`, `recall@K`를 제시한다.
2. 시간 구간별 성능과 블록 부트스트랩 신뢰구간을 추가한다.
3. SHAP을 “범죄 근거”가 아닌 “모델 내부 기여도”로 표시하고 익명 피처 한계를 화면에 노출한다.
4. 코드·모델·데이터·분할·임계값 해시를 포함한 평가 manifest를 최종 커밋에서 고정한다.
