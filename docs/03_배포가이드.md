# ChainEye(체인아이) 배포 가이드

2026 금융 AI Challenge 제출을 위해 ChainEye 서비스를 **하나의 공개 URL**로 배포하는 방법을 정리한다.
프론트엔드(React/Vite)와 백엔드(FastAPI + LightGBM/SHAP)를 **단일 Docker 이미지**로 묶어,
한 개의 프로세스가 `$PORT`(기본 7860)에서 API와 정적 프론트엔드를 동시에 서빙한다.

- **1순위 배포처: Hugging Face Spaces (Docker SDK)** — 무료 공개 URL, Docker 지원, Secret으로 API 키 주입 가능
- **대안: Render (Docker)** — 무료 티어 존재(콜드 스타트 있음)

관련 산출물:

- `Dockerfile` (프로젝트 루트) — 멀티스테이지 빌드(프론트 빌드 → 파이썬 런타임)
- `.dockerignore` — 665MB 원본 데이터셋·`node_modules`·`.venv` 등 제외
- `deploy/requirements.txt` — 백엔드 파이썬 의존성(모델 아티팩트와 호환되도록 버전 고정)
- `docker-compose.yml` (선택) — 로컬 테스트 편의용

---

## 0. 사전 준비

- 모델 아티팩트가 저장소에 포함되어 있어야 한다(용량 주의):
  - `app/ml/chaineye_model.pkl` (약 1.3MB)
  - `app/ml/feature_table.parquet` (약 **58MB**)
  - `app/ml/edges.parquet` (약 2.4MB)
  - `app/ml/shap_background.parquet`, `app/ml/inference.py`
- `data/elliptic_bitcoin_dataset/` (약 **665MB**)는 **런타임에 필요 없으며** 이미지에 절대 넣지 않는다
  (`.dockerignore`에서 제외됨).
- 58MB parquet 파일은 GitHub 일반 파일 한도(100MB) 이내이지만, Hugging Face에 직접 push할 경우
  Git LFS 사용을 권장한다(아래 1-2 참고).

## 1. Hugging Face Spaces 배포 (권장)

### 1-1. Space 생성

1. https://huggingface.co 로그인 → 우상단 **New → Space**
2. 항목 설정:
   - **Owner / Space name**: 예) `your-id/chaineye`
   - **License**: 자유 선택(예: `mit`)
   - **Select the SDK**: **Docker** → **Blank** 템플릿
   - **Space hardware**: `CPU basic` (무료)로 충분
   - **Visibility**: **Public** (공모전 심사용 공개 URL 필요)
3. 생성하면 다음 형태의 공개 URL이 발급된다:
   `https://huggingface.co/spaces/your-id/chaineye`
   실제 앱은 `https://your-id-chaineye.hf.space` 에서 렌더링된다.

### 1-2. README front-matter 추가 (필수)

Spaces는 저장소 루트 `README.md` 상단의 YAML front-matter로 Docker 설정을 읽는다.
**저장소 루트에 아래 내용으로 `README.md`를 만든다(또는 기존 파일 상단에 블록을 추가)**:

```markdown
---
title: ChainEye
emoji: 🔎
colorFrom: indigo
colorTo: blue
sdk: docker
app_port: 7860
pinned: false
---

# ChainEye (체인아이)
비트코인 자금세탁 탐지 서비스 — 2026 금융 AI Challenge
```

- `sdk: docker` → 루트 `Dockerfile`로 빌드
- `app_port: 7860` → 컨테이너가 리슨하는 포트를 Spaces에 알림(우리 Dockerfile 기본값과 일치)

> 참고: 본 `Dockerfile`은 `$PORT`(기본 7860)를 사용하므로 Spaces가 `PORT`를 주입해도 그대로 동작한다.

### 1-3. 저장소 push

이미 GitHub 저장소가 있다면 Space를 원격으로 추가해 push 한다.
(58MB parquet 때문에 Git LFS 사용을 권장)

```bash
# 저장소 루트에서
git lfs install
git lfs track "*.parquet" "*.pkl"
git add .gitattributes

git add Dockerfile .dockerignore deploy/ app/ README.md docs/
git commit -m "Deploy ChainEye to HF Spaces (Docker)"

# Space를 원격으로 추가 (HF 사용자명/스페이스명에 맞게 수정)
git remote add space https://huggingface.co/spaces/your-id/chaineye
git push space main
```

인증은 Hugging Face **Access Token**(Settings → Access Tokens, `write` 권한)을 비밀번호 대신 입력한다.

push 후 Space의 **Building** 로그가 자동으로 뜨고, 빌드가 끝나면 **Running** 상태가 된다.
(첫 빌드는 파이썬 의존성 설치 때문에 수 분 소요)

### 1-4. ANTHROPIC_API_KEY Secret 등록 (선택, LLM 보고서용)

현재 `/report`는 템플릿 기반으로 **키 없이도 동작**한다. 향후 Claude 기반 서술형 보고서를
켜려면 키를 Secret으로 주입한다(코드에 절대 하드코딩하지 않는다):

1. Space 페이지 → **Settings** → **Variables and secrets**
2. **New secret** 클릭
   - **Name**: `ANTHROPIC_API_KEY`
   - **Value**: `sk-ant-...`
3. 저장 후 **Restart this Space**

컨테이너 안에서는 환경변수 `ANTHROPIC_API_KEY`로 노출된다.

### 1-5. 동작 확인

- 앱 URL: `https://your-id-chaineye.hf.space` → 프론트엔드 화면
- 헬스체크: `https://your-id-chaineye.hf.space/health` → `{"status":"ok","modelLoaded":true}`
  - `modelLoaded: true`면 실제 LightGBM 모델(MODEL 모드)로 서빙 중
  - `false`면 모델 로딩 실패로 MOCK 모드(아티팩트 경로/누락 확인 필요)
- API 예시:
  ```bash
  curl -X POST https://your-id-chaineye.hf.space/score \
    -H "Content-Type: application/json" \
    -d '{"txId":"230425980"}'
  ```

## 2. 로컬 Docker 테스트 (배포 전 검증)

Spaces에 올리기 전에 로컬에서 동일 이미지를 빌드·구동해 검증한다.

```bash
# 프로젝트 루트에서 빌드 (프론트엔드도 이미지 안에서 빌드됨)
docker build -t chaineye:latest .

# 실행 (호스트 7860 → 컨테이너 7860)
docker run --rm -p 7860:7860 chaineye:latest

# LLM 보고서까지 테스트하려면 키를 주입
docker run --rm -p 7860:7860 -e ANTHROPIC_API_KEY=sk-ant-... chaineye:latest
```

- 브라우저: http://localhost:7860
- 헬스체크: http://localhost:7860/health
- API 문서(FastAPI 자동): http://localhost:7860/docs

docker compose를 쓰면 더 간단하다:

```bash
docker compose up --build      # http://localhost:7860
docker compose down
```

> 다른 포트로 띄우려면: `docker run --rm -p 8080:8080 -e PORT=8080 chaineye:latest`

## 3. 대안: Render (Docker)

1. https://render.com 로그인 → **New → Web Service**
2. GitHub 저장소 연결 → 다음 설정:
   - **Runtime / Language**: **Docker** (루트 `Dockerfile` 자동 감지)
   - **Instance Type**: `Free` (콜드 스타트 있음)
   - **Environment Variables**:
     - (선택) `ANTHROPIC_API_KEY = sk-ant-...`
   - 포트는 Render가 `PORT` 환경변수로 주입하며, 우리 `Dockerfile`이 `$PORT`를 사용하므로
     별도 설정 없이 동작한다.
3. **Create Web Service** → 빌드 완료 후 `https://chaineye.onrender.com` 형태의 공개 URL 발급.

> 주의: Render 무료 티어는 유휴 시 슬립 → 첫 요청이 느릴 수 있다. 심사 직전 한 번 워밍업 요청을 보내둔다.

## 4. 아키텍처 요약 / 주의사항

- **단일 프로세스 서빙**: `uvicorn`이 `app/backend/main.py`를 구동하고, 백엔드가
  `app/frontend/dist`를 정적 파일로 서빙한다(같은 오리진 → CORS 문제 없음).
- **모델 로딩(loose coupling)**: 시작 시 `app/ml/inference.py`를 임포트해 로드에 성공하면
  MODEL 모드, 실패하면 자동으로 MOCK 모드로 폴백한다(서비스는 항상 응답).
- **의존성 버전 고정**: `deploy/requirements.txt`는 모델 pickle과 호환되도록
  `lightgbm==4.7.0`, `scikit-learn==1.9.0` 등으로 고정했다. 임의로 올리면
  `joblib.load()` 시 경고/오류가 날 수 있다.
- **이미지 용량**: 파이썬 과학계산 스택(numpy/scipy/scikit-learn/lightgbm/shap) + 58MB
  parquet 포함으로 최종 이미지가 수백 MB~1GB 초반대가 될 수 있다. Spaces/Render 모두 수용 가능.
- **LightGBM 런타임 의존성**: 슬림 이미지에서 LightGBM 임포트에 `libgomp1`(OpenMP)이 필요하여
  `Dockerfile`에서 설치한다.
- **원본 데이터셋 제외**: 665MB `data/` 는 `.dockerignore`로 제외된다. 이미지에 절대 포함하지 않는다.

### 알려진 이슈 / 배포 전 체크

- **프론트엔드 `USE_MOCK`**: `app/frontend/src/config.js`의 `USE_MOCK`가 `true`이면 화면이
  샘플(mock) 데이터로 동작하고 백엔드 API를 호출하지 않는다. **실모델 데모가 필요하면 배포 전
  `USE_MOCK=false`로 두어야 한다**(해당 파일은 프론트 담당이 관리).
- **정적 서빙 코드**: 백엔드가 `app/frontend/dist`를 정적 서빙하는 부분(StaticFiles 마운트)은
  백엔드 담당이 추가한다. 이 부분이 반영되어야 루트 URL(`/`)에서 화면이 뜬다. 미반영 상태여도
  이미지 빌드/구동과 API(`/score`, `/health` 등)는 정상 동작한다.
