# 체인아이(ChainEye) 기획서

가상자산 AML 모델 판단 보증·조사 지원 웹서비스
2026 금융 AI Challenge 제출

비트코인 거래 분류 모델의 점수뿐 아니라 적용 범위, 판단 거부, 검토 후보 경로와 모델 내부 기여도를 함께 보여준다. 목표는 범죄를 확정하는 것이 아니라 분석관이 모델의 출력을 어디까지 믿을 수 있는지 감사하고 다음 조사를 결정하도록 돕는 것이다.

라이브 서비스: https://chaineye.onrender.com
소스 코드: https://github.com/ssophiz/chaineye

(무료 호스팅이라 15분 동안 접속이 없으면 절전 상태로 들어간다. 이때 첫 접속은 30~60초 정도 기다리면 깨어난다.)

## 1. 왜 만들었나

가상자산은 이미 자금세탁의 주요 통로가 됐다. 국내에서도 보이스피싱·불법도박·마약 대금이 거래소를 거쳐 비트코인으로 세탁되는 사건이 늘고 있다. 그런데 이걸 잡아내는 현장은 아직 손이 많이 간다.

블록체인 익스플로러로 트랜잭션을 하나씩 눌러가며 자금을 따라가는 방식은 느리다. 여러 지갑을 거치며 잘게 쪼개는 peeling chain이나 믹서를 통과하는 흐름은 사람 눈으로 쫓기가 특히 어렵다. STR(의심거래보고)을 쓸 때도 "왜 의심되는가"를 숫자로 설명하기가 쉽지 않다. 이상 거래를 탐지하는 모델이 있어도, 그 결과를 실제 수사 착수나 보고서로 옮기는 마지막 단계는 결국 사람 몫으로 남는다.

체인아이는 점수, 판단 거부, 경로 가설을 서로 다른 출력으로 관리한다. 데이터 범위 밖 거래는 0점 정상으로 처리하지 않고 평가 불가로 중단하며, 그때 자동 보고서와 STR 권고도 만들지 않는다.

## 2. 누가 쓰나

| 사용자 | 무엇에 쓰나 |
|---|---|
| 가상자산 사업자(VASP) 컴플라이언스팀 | 모델 경보의 적용 범위와 검토 우선순위를 확인 |
| 금융정보분석원(FIU)·수사기관 | 후보 흐름을 눈으로 확인하고 후속 조사 대상을 좁힘 |
| 모델 리스크·검증 담당자 | 시간 분할, 임계값, 판단 거부와 분석관 검토량을 감사 |

## 3. 어떻게 동작하나

Elliptic 데이터셋의 거래 ID를 넣으면 세 가지가 나온다. 실제 지갑 주소나 실거래 64자리 txid는 현재 모델 입력이 아니며 점수를 산출하지 않는다.

첫째, 위험 점수다. 학습된 모델이 그 거래가 불법일 확률을 0에서 100 사이 값으로 매긴다.

둘째, 자금흐름 추적 그래프다. 대상 거래의 위·아래 흐름을 그래프로 그리고, 검증에서 선택한 모델 임계값 이상의 노드를 색으로 구분한다. 추적 로직은 대상 거래에서 모델 양성 노드로 이어지는 방향성 경로 가설을 최대 8개까지 뽑는다. 프론트엔드는 이를 주황색으로 강조하되, 확정된 세탁 경로가 아니라 분석관이 검토할 후보임을 명시한다.

셋째, 리포트다. 위험 등급과 모델 내부 기여도, 그래프 통계를 제공된 수치 범위 안에서 정리한다. Claude·OpenAI 생성 경로가 선택 기능으로 구현되어 있고, 키가 없거나 호출이 실패하면 결정론적 템플릿으로 폴백한다. 데이터 범위 밖이면 생성 자체를 억제한다.

## 4. 데이터

Elliptic Data Set을 쓴다. Elliptic사가 공개한, 익명화된 실제 비트코인 트랜잭션 그래프다.

- 노드 203,769개(트랜잭션), 엣지 234,355개(비트코인 흐름), 타임스텝 49개
- 노드마다 피처 166개. 앞 94개는 거래 자체 정보(입출력 수, 수수료, 타임스텝 등)이고, 나머지 72개는 이웃 트랜잭션을 집계한 값이다.
- 라벨은 불법 2%(4,545개), 합법 21%(42,019개), 나머지 77%는 미분류다.

목업이 아니라 공개된 실데이터로 학습하고 검증했다는 점이 중요하다. 규모를 더 키우려면 Elliptic++나 서브그래프 단위의 Elliptic2로 확장할 여지도 있다.

## 5. 모델

두 갈래로 접근했다. 하나는 실제 서비스를 돌리는 라이브 모델, 다른 하나는 그래프 구조를 보는 보완 모델이다.

라이브 모델은 LightGBM이다. 시간축으로 데이터를 학습 1~30, 검증 31~34, 최종 테스트 35~49로 나눴다. 검증 구간에서 반복 수와 판정 임계값을 정하고 최종 테스트는 모델 선택에 쓰지 않았다. 피처는 time_step을 뺀 165개다. 독립 테스트 기준 불법 클래스 Precision 0.698, Recall 0.723, F1 0.711, PR-AUC 0.674, ROC-AUC 0.899다. 검증에서 선택된 판정 임계값은 0.226이며 테스트 1,000건당 약 67건이 분석관 검토 대상으로 올라온다. 초기 결과 F1 0.776은 최종 테스트를 early stopping에 사용한 낙관적 수치였으므로 현재 대표 성능으로 사용하지 않는다. 현재 /score는 이 LightGBM 하나로 서빙한다.

보완 모델은 GCN 탐색 산출물이다. PyTorch Geometric으로 GCNConv 세 층을 구현했지만, 이 과거 실행은 검증 구간 없이 테스트 지표를 학습 중 확인한 구조 실험이다. 불법 F1 0.562, ROC-AUC 0.892는 라이브 LightGBM과 직접 비교하거나 성능 개선으로 주장하지 않는다. 코드는 `app/ml/gcn/` 아래에 격리되어 있고 라이브 추론에는 연결하지 않았다.

판정 근거는 SHAP으로 만든다. 각 판정에서 어떤 피처가 위험도를 끌어올렸는지 기여도를 뽑아 리포트에 넣는다.

리포트 본문은 점수, 상위 SHAP 기여도, 그래프 통계를 받아 사람이 읽을 수 있는 문장으로 정리한다. 외부 생성형 AI 경로는 구현되어 있으나 선택 사항이며, 키가 없는 공개 데모는 동일 입력에 동일 결과를 내는 템플릿 경로를 사용한다.

## 6. 시스템 구성

```
프론트엔드(React + Cytoscape.js)
   Elliptic 거래 ID 입력, 점수·그래프·리포트 표시
        |
백엔드(FastAPI)
   /score    LightGBM 추론으로 불법 확률 산출 (라이브 서빙)
   /trace    상·하류 서브그래프 + 분석 검토 후보 경로(최대 8개)
   /explain  SHAP 상위 기여 피처
   /report   선택형 생성 AI + 결정론적 템플릿 폴백
        |
모델·데이터
   라이브 모델 = LightGBM(.pkl) + 전처리된 Elliptic 그래프
   병렬 그래프 모델 = GCN(.pt, app/ml/gcn/), 평가 완료·미연동
        |
배포: Render(Docker) 공개 URL
```

서빙 경로는 LightGBM 하나다. GCN은 같은 데이터로 학습·평가를 마친 병렬 모델로, 그래프 구조 신호를 보완하는 자리에 둔다. 앙상블 연동은 이후 과제다.

## 7. 다른 프로젝트와 뭐가 다른가

체인아이의 차별점은 상용 추적 도구를 대체하는 것이 아니라 모델 출력 계약을 공개하는 데 있다. 점수 산출이 가능한 입력, 데이터 범위 밖 판단 거부, 방향성 경로 가설을 API와 화면에서 구분한다. 특히 평가 불가일 때 자동 보고서와 STR 권고까지 억제하므로, 조회 결과 없음이 정상 판정으로 오인되는 실패를 막는다.

설계 관점도 다르다. 침해사고 대응 실무 경험을 바탕으로, 수사관과 컴플라이언스 담당자가 실제로 손에 쥐고 쓰는 화면을 기준으로 만들었다.

주제 면에서도 과거 회차의 일반적인 이상금융거래 분류와 구분된다. 가상자산, 그래프, 설명가능성이라는 축이 새롭다.

## 8. 어디까지 왔나

현재 작성 시점(2026년 8월 19일)에 아래는 모두 만들어져 실제로 돌아간다.

- Elliptic 데이터 전처리와 LightGBM 학습. 독립 시간 테스트 기준 불법 F1 0.711, PR-AUC 0.674, ROC-AUC 0.899.
- GCN 학습·평가. 과거 탐색 분할에서 불법 F1 0.562, ROC-AUC 0.892이며 현재 LightGBM과 직접 비교하지 않는다.
- 서브그래프 추적과 분석 검토 후보 경로 하이라이트, SHAP 근거 제시.
- 점수, 그래프, 리포트로 이어지는 엔드투엔드 흐름과 프론트엔드 화면.
- Render에 배포한 공개 URL(https://chaineye.onrender.com).

아직 안 한 것도 분명히 적어둔다. 생성형 AI 보고서는 선택 경로로 구현되어 있지만 공개 데모는 키 없이 템플릿 폴백을 사용한다. GCN은 비교 가능한 재평가 전까지 라이브 추론과 발표 성능 비교에서 제외한다.

## 9. 기대효과와 확장

기대효과는 모델 경보를 곧바로 사건 판단으로 받아들이는 위험을 줄이고, 분석관이 검토할 입력을 일관된 형식으로 제공하는 것이다. 시간 절감과 실무 채택 효과는 제출 전 별도 사용자 검증으로 측정하며, 현재 구현만으로 확정해 주장하지 않는다.

서비스의 뼈대는 특정 코인에 묶여 있지 않다. 그래프와 테이블 데이터를 받아 위험을 매기고, 흐름을 추적하고, 근거를 붙여 리포트를 내는 구조라서, 데이터 계층만 갈아 끼우면 다른 기관도 자기 환경에 맞춰 쓸 수 있다.

| 도입 주체 | 커스텀 방식 | 기대 효과 |
|---|---|---|
| 가상자산 거래소·VASP | 자사 입출금·온체인 데이터로 재학습 | 세탁자금 유입 차단, 트래블룰 대응 |
| 은행·FIU | 계좌 이체 네트워크로 그래프 구성 | 보이스피싱·대포통장 자금흐름 추적, STR 자동화 |
| 카드사·보험사 | 거래/청구 데이터에 적용 | 이상거래·보험사기 탐지 |
| 다른 블록체인 | 이더리움 등으로 확장 | 멀티체인 자금세탁 추적 |

물론 실제로 도입하려면 넘어야 할 조건이 있다. 기관마다 자체 라벨 데이터와 피처 엔지니어링이 필요하다(Elliptic의 익명화 피처는 그대로 재현할 수 없다). 인증과 권한, 감사 로그 같은 운영 보안도 갖춰야 한다. LLM 리포트는 반드시 제공된 수치에만 근거해 생성하고, 담당자가 마지막에 검토하는 절차를 두어야 한다. 지금 만든 것은 그 확장의 출발점이 되는 작동하는 원형이다.

자금세탁 추적은 보이스피싱이나 마약, 불법도박 같은 범죄수익의 흐름을 끊고 피해 자금 회수를 돕는 일이다. 다만 이 도구는 담당자의 판단을 돕는 보조 수단이고, 최종 결정은 사람이 한다는 선을 지킨다.
