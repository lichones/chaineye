# 체인아이(ChainEye) 기획서

가상자산 자금세탁 탐지·추적 AI 웹서비스
2026 금융 AI Challenge 제출

비트코인 거래 그래프에서 자금세탁이 의심되는 흐름을 찾아내고, 그 자금이 어디서 와서 어디로 가는지 추적해 보여준다. 판정 근거와 함께 수사·컴플라이언스 담당자가 바로 쓸 수 있는 한국어 리포트까지 자동으로 만든다.

라이브 서비스: https://chaineye.onrender.com
소스 코드: https://github.com/ssophiz/chaineye

(무료 호스팅이라 15분 동안 접속이 없으면 절전 상태로 들어간다. 이때 첫 접속은 30~60초 정도 기다리면 깨어난다.)

---

## 1. 왜 만들었나

가상자산은 이미 자금세탁의 주요 통로가 됐다. 국내에서도 보이스피싱·불법도박·마약 대금이 거래소를 거쳐 비트코인으로 세탁되는 사건이 늘고 있다. 그런데 이걸 잡아내는 현장은 아직 손이 많이 간다.

블록체인 익스플로러로 트랜잭션을 하나씩 눌러가며 자금을 따라가는 방식은 느리다. 여러 지갑을 거치며 잘게 쪼개는 peeling chain이나 믹서를 통과하는 흐름은 사람 눈으로 쫓기가 특히 어렵다. STR(의심거래보고)을 쓸 때도 "왜 의심되는가"를 숫자로 설명하기가 쉽지 않다. 이상 거래를 탐지하는 모델이 있어도, 그 결과를 실제 수사 착수나 보고서로 옮기는 마지막 단계는 결국 사람 몫으로 남는다.

체인아이는 이 세 지점, 즉 탐지하고 추적하고 근거를 만들어 보고서까지 잇는 과정을 하나로 묶었다.

## 2. 누가 쓰나

| 사용자 | 무엇에 쓰나 |
|---|---|
| 가상자산 사업자(VASP) 컴플라이언스팀 | STR 작성 시간을 줄이고, 탐지 근거를 정량화·표준화 |
| 금융정보분석원(FIU)·수사기관 | 자금흐름을 눈으로 추적하고, 자동 리포트로 초동 대응을 앞당김 |
| 거래소 리스크팀 | 입금 주소를 실시간으로 스코어링해 세탁자금 유입을 걸러냄 |

## 3. 어떻게 동작하나

거래 ID(또는 주소)를 넣으면 세 가지가 나온다.

첫째, 위험 점수다. 학습된 모델이 그 거래가 불법일 확률을 0에서 100 사이 값으로 매긴다.

둘째, 자금흐름 추적 그래프다. 대상 거래의 위·아래 흐름을 그래프로 그리고, 위험한 노드를 색으로 구분한다. 여기서 추적 로직이 대상 거래에서 위험도 70 이상인 노드로 이어지는 의심 경로를 최대 8개까지 뽑아낸다. 프론트엔드는 이 경로를 주황색으로 강조하고 "의심 자금세탁 경로"라고 표시해서, 여러 단계를 거치는 세탁 흐름을 한눈에 보이게 한다.

셋째, 리포트다. 위험 등급과 판단 근거(어떤 피처가 위험을 끌어올렸는지), 권고 조치를 담아 자동으로 작성한다. 지금은 템플릿 기반이고, LLM 연동은 다음 단계로 잡아뒀다.

## 4. 데이터

Elliptic Data Set을 쓴다. Elliptic사가 공개한, 익명화된 실제 비트코인 트랜잭션 그래프다.

- 노드 203,769개(트랜잭션), 엣지 234,355개(비트코인 흐름), 타임스텝 49개
- 노드마다 피처 166개. 앞 94개는 거래 자체 정보(입출력 수, 수수료, 타임스텝 등)이고, 나머지 72개는 이웃 트랜잭션을 집계한 값이다.
- 라벨은 불법 2%(4,545개), 합법 21%(42,019개), 나머지 77%는 미분류다.

목업이 아니라 공개된 실데이터로 학습하고 검증했다는 점이 중요하다. 규모를 더 키우려면 Elliptic++나 서브그래프 단위의 Elliptic2로 확장할 여지도 있다.

## 5. 모델

두 갈래로 접근했다. 하나는 실제 서비스를 돌리는 라이브 모델, 다른 하나는 그래프 구조를 보는 보완 모델이다.

라이브 모델은 LightGBM이다. 시간축으로 데이터를 나눠(학습은 타임스텝 1~34, 테스트는 35~49) 미래 데이터가 새어들지 않게 했고, 피처는 time_step을 뺀 165개를 썼다. 테스트 기준 불법 클래스 F1이 0.776, ROC-AUC가 0.936이다. 불법이 2%뿐인 불균형은 class weight로 보정했다. 데이터가 불균형해서 정확도(Accuracy)는 오해를 부르기 쉬우므로 F1과 ROC-AUC를 봤다. 현재 /score는 이 LightGBM 하나로 서빙한다.

보완 모델은 GCN이다. PyTorch Geometric으로 GCNConv 세 층을 쌓아 트랜잭션 사이의 연결까지 학습한다. 라이브 모델과 같은 시간축 분할로 평가했고 불법 F1은 0.562, ROC-AUC는 0.892가 나왔다. F1이 트리 모델보다 낮은 건, Elliptic의 수작업 피처 165개가 이미 트리에 잘 먹히기 때문이다. 대신 GCN은 트리가 놓치는 관계·구조 신호, 예컨대 layering이나 peel chain, 믹서에서의 fan-out 같은 패턴을 잡는다. 그래서 대체가 아니라 앙상블 후보로 봤다. 코드는 app/ml/gcn/ 아래 따로 두었고, 아직 라이브 추론이나 백엔드에는 연결하지 않았다.

판정 근거는 SHAP으로 만든다. 각 판정에서 어떤 피처가 위험도를 끌어올렸는지 기여도를 뽑아 리포트에 넣는다.

리포트 본문은 점수, 상위 SHAP 근거, 그래프 통계를 받아 사람이 읽을 수 있는 문장으로 정리한다. 지금은 템플릿으로 생성하고, Claude API 연동은 예정된 개선 항목이다.

## 6. 시스템 구성

```
프론트엔드(React + Cytoscape.js)
   거래 ID/주소 입력, 점수·그래프·리포트 표시
        |
백엔드(FastAPI)
   /score    LightGBM 추론으로 불법 확률 산출 (라이브 서빙)
   /trace    상·하류 서브그래프 + 의심 자금세탁 경로(최대 8개)
   /explain  SHAP 상위 기여 피처
   /report   템플릿 기반 리포트 (Claude API 연동 예정)
        |
모델·데이터
   라이브 모델 = LightGBM(.pkl) + 전처리된 Elliptic 그래프
   병렬 그래프 모델 = GCN(.pt, app/ml/gcn/), 평가 완료·미연동
        |
배포: Render(Docker) 공개 URL
```

서빙 경로는 LightGBM 하나다. GCN은 같은 데이터로 학습·평가를 마친 병렬 모델로, 그래프 구조 신호를 보완하는 자리에 둔다. 앙상블 연동은 이후 과제다.

## 7. 다른 프로젝트와 뭐가 다른가

비슷한 프로젝트는 대개 분류 정확도에서 멈춘다. 체인아이는 거기서 더 나아가 추적 시각화와 근거 제시, 자동 리포트까지 붙였다. 특히 대상 거래에서 고위험 노드로 이어지는 의심 경로를 자동으로 뽑아 주황색으로 강조하기 때문에, 여러 단계를 거치는 세탁 흐름이 바로 눈에 들어온다.

설계 관점도 다르다. 침해사고 대응 실무 경험을 바탕으로, 수사관과 컴플라이언스 담당자가 실제로 손에 쥐고 쓰는 화면을 기준으로 만들었다.

주제 면에서도 과거 회차의 일반적인 이상금융거래 분류와 구분된다. 가상자산, 그래프, 설명가능성이라는 축이 새롭다.

## 8. 어디까지 왔나

지금 제출하는 시점(2026년 8월 13일)에 아래는 모두 만들어져 실제로 돌아간다.

- Elliptic 데이터 전처리와 LightGBM 학습. 시간축 분할 기준 불법 F1 0.776, ROC-AUC 0.936.
- GCN 학습·평가. 같은 분할에서 불법 F1 0.562, ROC-AUC 0.892.
- 서브그래프 추적과 의심 자금세탁 경로 하이라이트, SHAP 근거 제시.
- 점수, 그래프, 리포트로 이어지는 엔드투엔드 흐름과 프론트엔드 화면.
- Render에 배포한 공개 URL(https://chaineye.onrender.com).

아직 안 한 것도 분명히 적어둔다. 리포트의 LLM 연동은 지금 템플릿으로 대체하고 있고, GCN을 라이브 추론에 앙상블로 붙이는 작업은 다음 단계로 남겨뒀다. 둘 다 서비스 동작에는 지장이 없다.

## 9. 기대효과와 확장

STR이나 수사 착수를 판단하는 데 드는 시간을 손으로 할 때보다 크게 줄일 수 있다. "의심"의 근거를 숫자와 설명으로 표준화하면 보고 품질과 신뢰도도 올라간다.

서비스의 뼈대는 특정 코인에 묶여 있지 않다. 그래프와 테이블 데이터를 받아 위험을 매기고, 흐름을 추적하고, 근거를 붙여 리포트를 내는 구조라서, 데이터 계층만 갈아 끼우면 다른 기관도 자기 환경에 맞춰 쓸 수 있다.

| 도입 주체 | 커스텀 방식 | 기대 효과 |
|---|---|---|
| 가상자산 거래소·VASP | 자사 입출금·온체인 데이터로 재학습 | 세탁자금 유입 차단, 트래블룰 대응 |
| 은행·FIU | 계좌 이체 네트워크로 그래프 구성 | 보이스피싱·대포통장 자금흐름 추적, STR 자동화 |
| 카드사·보험사 | 거래/청구 데이터에 적용 | 이상거래·보험사기 탐지 |
| 다른 블록체인 | 이더리움 등으로 확장 | 멀티체인 자금세탁 추적 |

물론 실제로 도입하려면 넘어야 할 조건이 있다. 기관마다 자체 라벨 데이터와 피처 엔지니어링이 필요하다(Elliptic의 익명화 피처는 그대로 재현할 수 없다). 인증과 권한, 감사 로그 같은 운영 보안도 갖춰야 한다. LLM 리포트는 반드시 제공된 수치에만 근거해 생성하고, 담당자가 마지막에 검토하는 절차를 두어야 한다. 지금 만든 것은 그 확장의 출발점이 되는 작동하는 원형이다.

자금세탁 추적은 보이스피싱이나 마약, 불법도박 같은 범죄수익의 흐름을 끊고 피해 자금 회수를 돕는 일이다. 다만 이 도구는 담당자의 판단을 돕는 보조 수단이고, 최종 결정은 사람이 한다는 선을 지킨다.
