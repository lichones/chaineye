# ChainEye AML 실무자 검토 프로토콜

## 목적

RSAC 발표 제안서에 필요한 현업 검증 증거를 확보한다. 제품 만족도를 묻는 인터뷰가 아니라, 모델 출력이 분석관에게 잘못된 확신을 주는지와 어떤 근거가 실제 의사결정에 필요한지를 확인한다.

## 권장 검토자

- VASP·은행·카드사 AML/컴플라이언스 담당자
- 블록체인 포렌식 또는 이상거래 조사 경험자
- FIU·수사기관 업무 경험자

최소 1명, 가능하면 서로 다른 조직의 3명을 권장한다. 이름과 조직 공개 여부는 검토자가 직접 선택한다. 고객정보, 실제 의심거래, 개인정보는 수집하지 않고 공개 Elliptic 사례만 사용한다.

## 검토 환경

- 모델: 독립 시간 분할로 재학습한 LightGBM
- 데모 사례 A: `68995268` — 모델 양성, 후보 경로 존재
- 데모 사례 B: `155699346` — 낮은 점수의 licit 테스트 거래
- 데모 사례 C: `999999999999` — 데이터 범위 밖, unknown/abstain
- 예상 시간: 35분
- 기록: 화면 녹화는 별도 동의가 있을 때만 사용. 기본은 익명 메모

## 진행 순서

### 1. 사전 질문 — 5분

1. 현재 의심거래 조사에서 위험점수, 그래프, 모델 설명을 사용하는가?
2. 거래를 추가 검토로 넘길 때 반드시 필요한 근거는 무엇인가?
3. 자동화 도구가 “모른다”고 답해야 하는 상황은 무엇인가?

### 2. 사례별 과제 — 각 7분

검토자에게 정답 라벨을 먼저 보여주지 않는다. 각 사례에서 다음 과제를 수행한다.

1. 화면만 보고 `추가 조사`, `보류`, `낮은 우선순위` 중 하나를 선택한다.
2. 선택에 사용한 화면 요소를 소리 내어 설명한다.
3. 신뢰할 수 없거나 의미를 알 수 없는 요소를 지적한다.
4. 보고서 문장 중 유지·삭제·수정할 문장을 표시한다.
5. 다음 단계로 진행하기 위해 필요한 추가 데이터를 말한다.

### 3. 사후 질문 — 9분

1. 0~100 점수와 모델 임계값 23점이 함께 표시될 때 의미가 명확했는가?
2. `illicit` 라벨이 “불법 확정”으로 오해될 가능성이 있는가? 더 적절한 용어는 무엇인가?
3. 주황색 경로가 확정된 자금세탁 경로가 아닌 후보 가설임을 이해했는가?
4. `feat_52` 같은 익명 SHAP 피처가 조사 근거로 유용한가?
5. unknown 화면이 0점 정상 판정보다 안전하고 실무적으로 유용한가?
6. STR 검토 전에 필요한 최소 증거 묶음은 무엇인가?

## 발표 제안서에 반영할 결과

검토가 끝나면 다음 네 문장을 실제 수치로 작성한다.

1. `[N]명의 AML/포렌식 실무자가 공개 사례 3건을 검토했다.`
2. `검토자는 [요소]는 채택했지만 [요소]는 [이유] 때문에 조사 근거로 거부했다.`
3. `unknown/abstain 처리는 [N/N]명이 기존 0점 정상 판정보다 안전하다고 평가했다.`
4. `피드백 후 [UI·API·보고서 변경]을 적용했고, 첫 판단 시간 또는 이해도는 [전/후 결과]로 변했다.`

소속이나 이름을 공개할 수 없으면 “three AML practitioners from Korean financial and virtual-asset organizations”처럼 검토자가 승인한 범위만 사용한다. 인터뷰를 하지 못했다면 제안서에서 case study를 주장하지 않고, “structured expert review is planned”라고 정직하게 낮춰 쓴다.
