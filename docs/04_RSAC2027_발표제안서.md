## 2. Session Title

**An Illicit Score Is Not an AML Case: Lessons from a Bitcoin Graph**

제목 제한: 공백 포함 75자 이내.

## 3. Session Detail

> 온라인 양식에는 아래 영문 본문만 붙여 넣는다. 불릿을 지원하지 않으므로 문단형으로 작성했다. 제한: 공백 포함 2,500자.

Security teams increasingly use machine-learning risk scores to triage cryptocurrency transactions, but a high score is not proof of money laundering. We learned this while turning the public Elliptic Bitcoin benchmark into ChainEye, a working investigation pipeline that combines temporal LightGBM scoring, SHAP explanations, directed graph tracing, and human-readable case summaries.

The session opens with a live walkthrough from a transaction ID to a risk score, local graph, candidate paths, and analyst report. We then examine where the apparently coherent workflow can mislead an investigator. The public labels identify transactions initiated by illicit entities, not confirmed laundering paths. Anonymous feature names make mathematically valid SHAP values difficult to defend as investigative evidence. A transaction missing from the benchmark cannot safely be called licit. Most importantly, our first evaluation used the final test window for early stopping, so its F1 score of 0.776 was not an independent estimate.

Rather than presenting another model leaderboard, we use these failures to build a practical validation pattern. We separate chronological training (steps 1–30), validation (31–34), and final test windows (35–49); introduce an explicit unknown/abstain outcome; and distinguish node-risk evidence from path-level hypotheses. On the untouched test window, the corrected baseline reaches 0.698 precision, 0.723 recall, 0.711 F1, 0.674 PR-AUC, and 0.899 ROC-AUC, with 67 reviews per 1,000 transactions at the validation-selected threshold. The graph model remains an illustrative experiment, not a claimed improvement. A second case study, reviewed by `[제출 전 입력: AML/컴플라이언스 검토자 또는 파일럿 기관]`, shows which evidence an analyst accepted, rejected, or requested before escalation.

Attendees will leave with a reusable checklist for auditing temporal leakage, a decision contract for score/unknown/path outputs, and a method for converting model explanations into evidence that preserves uncertainty. The code and evaluation artifacts will be shared in a vendor-neutral repository. The goal is not to automate suspicious-activity decisions, but to make machine assistance testable, reviewable, and safe to challenge.

## 4. Public Abstract

> 제한: 공백 포함 400자. 웹사이트와 행사 앱에 공개되는 문구.

An illicit-transaction score is not a money-laundering case. This session shows how a public Bitcoin benchmark became an explainable investigation workflow—and where it failed. Attendees will learn to detect temporal leakage, separate node risk from laundering-path hypotheses, handle unknown transactions safely, and design evidence an analyst can review and challenge.

## 11. 한국어 요약

이 발표의 주장은 “ChainEye가 자금세탁을 자동 판정한다”가 아니다. 공개 데이터로 만든 위험점수·그래프·설명 시스템이 실제 조사 도구처럼 보이기 시작할 때 어떤 잘못된 확신이 생기는지 보여주고, 이를 평가 분리, unknown 처리, 경로 가설 표시, 검토 가능한 설명으로 바로잡는 과정을 공유한다. 청중은 같은 실수를 피할 수 있는 평가 체크리스트와 출력 계약을 가져간다.
